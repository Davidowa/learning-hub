# Legacy exercise 12 · Subtotals, and a first PivotTable

Two hundred and forty-five order lines from an online clothing shop, summarised three times with the **Subtotal** dialog and then three more times with a PivotTable, so the same three questions get answered twice by two different tools. Six tasks, no formulas, and the whole point is the comparison at the end. This is the previous years' version of the subtotal exercise; the current set splits the same ground across [exercise 22](../ex22.en.md), which is subtotals over Mexico City population data, and [exercise 23](../ex23.en.md), which is PivotTables. Neither uses this workbook, so the clothing data survives only here. The student hands in the workbook with the subtotalled copies and the three reports.

**Objectives** MO-200 3.3.2, MO-201 2.2.3, MO-201 2.2.4, MO-201 4.2.1

## The data

One sheet, `Datos ropa`. Twelve columns in `B1:M246`: headings in row 1, 245 order lines in rows 2 to 246. One row per item bought, so an order of fourteen garments is fourteen rows sharing an order number, a date, a channel and a commission rate.

File: [labs/legacy/data/12-1-excel-12-students-subtotals--datos-ropa.csv](data/12-1-excel-12-students-subtotals--datos-ropa.csv), 246 rows by 12 columns, which is the 245 order lines plus the heading row.

The rows arrive already sorted ascending by `Order No.`, and by nothing else. That matters for the tasks: the first subtotal works without sorting anything, and the second and third do not.

The sheet carries no conditional formatting, no data validation, no sheet protection, no charts, no PivotTables and no table objects, so the CSV loses nothing except column widths and number formats.

## What to do

The source is four lines long. It is reproduced here in full, and everything after it in this section is the reading needed to make it gradeable, not text from the original.

1. Perform a subtotal analysis by Order.
2. Perform a subtotal analysis by gender.
3. Perform a subtotal analysis by platform.
4. Insert a pivot table to perform each of the analyses made with subtotals, by order, by gender and by platform.

The source names neither the summary function nor the column to summarise. `Price` is the only column in the sheet worth adding: `Comission` is a rate rather than an amount, and `Order No.` is an identifier. Sum of `Price` is what the Checks below assume, and any other function has to be graded against a recalculated key.

The source also does not say whether the three subtotals go on three copies of the sheet or on top of each other. Three copies is the workable reading, because **Subtotal** with **Replace current subtotals** cleared stacks the second break on top of the first, and with it ticked the third pass erases the second. Copy `Datos ropa` twice before starting and work one break per sheet.

Route for the sort before each pass: MO-200 3.3.2. Route for the **Subtotal** dialog: MO-201 2.2.4. Route for collapsing the outline afterwards: MO-201 2.2.3. Route for the three PivotTables: MO-201 4.2.1. The click paths are written out in [exercise 22](../ex22.en.md) for the first three and [exercise 23](../ex23.en.md) for the fourth.

Sort by the break column before every pass. Subtotals break wherever the value in the break column changes, so unsorted data gives one group per run of equal values instead of one group per value. `Order No.` is already sorted; `Gender` and `Platform` are not, and skipping the sort on those two is the mistake this exercise exists to produce.

## Notes on the source

- **The instructions are four lines and leave three things open**: which column to summarise, which function to summarise it with, and whether the three passes go on three sheets or one. Sum of `Price` on three copies is the reading used above, and it is a reading, not the source.
- **`Comission` is misspelled** in the heading of column G, one m short. Left as it is here so the field name matches the sheet.
- **`Womenes` is not a word.** Column J holds `Men` and `Womenes` for what should be Women. It is the value, not just a label, so correcting it means editing 154 cells and the PivotTable field, and both files have to be corrected together or neither.
- **`Underware` in column K** should be Underwear. Same argument as above: it is a value in 28 rows.
- **Products are in Spanish while every heading and code value is in English.** `Pants de Entrenamiento Reactivo`, `Sudadera sin Costuras`, `Bra Vital sin costuras` and seventy-one others. Nothing in the exercise reads the product names, so they are left alone.
- **Returns are counted as revenue.** Nineteen rows carry `Return` in column H, and their prices are positive, so they add to every total: 853 of the 9,922 is returned goods. The exercise never mentions it and no task filters them out. Whether that is intended is not recoverable from the source.
- **Commission is a rate and not an amount.** Column G is 0 for every house sale and between 0.1 and 0.4 for every influencer sale. Adding it is meaningless. Multiplying it by `Price` would give the amount owed, and nothing in the exercise asks for it.
- **The first task is the one that works by accident.** The data ships sorted by `Order No.`, so a student who never sorts still gets a correct subtotal on pass one, then a wrong one on passes two and three without changing anything about the way they worked. That is a good lesson if it is pointed out and an invisible trap if it is not.
- **The required-files line names a file that does not exist.** The .docx asks for `1 2.1 Excel 12 (students) Subtotals`; the folder holds `12.1 Excel_12 (students) Subtotals.xlsx`. The leading `1` and the space after it are a list marker that flattened into the filename, and the rest of the name has lost an underscore and gained a space.
- **The folder jumps from 12 to 14.** There is no `Ejercicio 13` anywhere in the previous years' material; see the note in [legacy exercise 14](ex14.en.md), whose instruction file is titled EXERCISE 13.
