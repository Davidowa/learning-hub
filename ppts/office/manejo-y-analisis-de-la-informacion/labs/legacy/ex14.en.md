# Legacy exercise 14 · PivotTables over a restaurant's tickets

Seven reports over 26,608 lines of restaurant tickets, one per row of a two-column table in the instruction file that pairs each question with the command that answers it. It is the file that carries the whole Expert PivotTable domain in the previous years' material: sorting inside a report, **Show Values As**, a report filter, date grouping, a calculated field, slicers, a timeline and a PivotChart, in that order. The student hands in the workbook with the seven reports on their own sheets.

There is no `Ejercicio 13` in the previous years' folder. The numbering runs 1 to 12, then 14, then 15, and the instruction file inside the `Ejercicio 14` folder is titled `EXERCISE 13- Exercise Pivot Tables` while its required-files line names `Exercise 14_Tables (students).xlsx`. Whatever exercise 13 was, it is not in the material, and the file that would have carried it left its title behind on this one.

**Objectives** MO-200 3.3.1, MO-200 3.3.2, MO-201 4.2.1, MO-201 4.2.2, MO-201 4.2.3, MO-201 4.2.4, MO-201 4.2.5, MO-201 4.3.1, MO-201 4.3.2

## The data

One sheet, `Restaurant`. Twelve columns in `A1:L26609`: headings in row 1 and 26,608 line items in rows 2 to 26,609. One row per line of a ticket, so an order of six dishes is six rows sharing an order number, a date, a time, a table, a waiter and a tip rate. Excel reports the used range as `A1:O26609`, three columns wider than the data, because columns M, N and O carry formatting and nothing else.

File: [labs/legacy/data/exercise-14-tables-students--restaurant.csv](data/exercise-14-tables-students--restaurant.csv), 26,609 rows by 12 columns, which is the 26,608 line items plus the heading row. Far past forty rows, so there is no inline table; the shape is below.

| Column | Heading | Contents |
|---|---|---|
| A | Order No. | 1 to 2500, repeated once per line of the ticket |
| B | Date | 1 February 2014 to 31 January 2015, 364 distinct days |
| C | Time | 48 distinct times, from 00:00 to 23:59 |
| D | Table | 1 to 17 |
| E | Waiter | 9 names |
| F | Type | `Food` 14,001 rows, `Beverages` 12,607 rows |
| G | Product | 69 items |
| H | Category | 10 groups |
| I | Price | what the customer pays, 18 to 758 |
| J | Cost | what the kitchen pays, 12.60 to 553.34 |
| K | Tip | a rate, 0.05 to 0.20, one value per order |
| L | Client Tye | `New` 19,812 rows, `Recurrent` 6,796 rows |

The nine waiters are Alejandro, Ernesto, Joel, Mariana, Mauricio, Omar, Rodolfo, Saul and Valentina. The ten categories are Beer, Desserts, Entrees, Main course, Non-alcoholic beverages, Pasta, Pizza, Salads, Tacos and Wine, and each one belongs to exactly one `Type`: Beer, Non-alcoholic beverages and Wine are Beverages, the other seven are Food. Every product maps to exactly one category at exactly one price and one cost, so nothing in the report has to resolve a conflict. There are no blanks in any of the twelve columns.

This is the same data as part B of the current [exercise 23](../ex23.en.md), which exports it as `labs/data/ex23-orders.csv`. The two files were compared row by row and differ only in how the export wrote dates and times. The sheet name is different, `Restaurant` here and `Datos restaurante` there, and that name is what a PivotTable shows as its source.

The sheet carries no conditional formatting, no data validation, no sheet protection, no charts, no PivotTables and no table objects, so the CSV loses nothing except column widths and number formats.

## What to do

The instruction file gives each task twice, once as a question and once as the command that answers it. Both columns are kept below, the command in italics.

1. Show the total charged per product, grouped by waiter. Order them from the best-selling product to the least. *Insert > Tables > PivotTable.* Waiter in Rows, Product in Rows beneath it, Sum of `Price` in Values. Routes: MO-201 4.2.1 for the report, MO-200 3.3.2 for the sort.
2. Show the same report as the previous question but as a percentage of total revenue. Sort them by product. *Value field settings.* **Show Values As**, **% of Grand Total**. Route: MO-201 4.2.2.
3. Show sales of each seller for each of the products, filtered by category, choosing soft drinks. *Filters in PivotTable.* Category goes into the **Filters** area rather than into Rows. There is no category called soft drinks; see the notes. Routes: MO-201 4.2.1 for the Filters area, MO-200 3.3.1 for the filter itself.
4. Show the average sales per category per month. *Value field settings.* Category in Rows, Date in Columns grouped by Months, Average of `Price` in Values. Routes: MO-201 4.2.4 for the grouping, MO-201 4.2.2 for the function.
5. Show the profit of each category, using a calculated field. Segment by seller and by Type. *Analyze PivotTable > Calculations > Fields, Items, and Assemblies > Calculated Field.* The field is `= Price - Cost`; the segmenting is two slicers, one on Waiter and one on Type. Routes: MO-201 4.2.5 for the field, MO-201 4.2.3 for the slicers.
6. Show the percentage of the overall total of sales for each of the waiters for each of the products. Use a timeline to select a specific month. *Value field settings. Analyze PivotTable > Filter > Insert Timeline.* Waiter in Rows, Product in Columns, Sum of `Price` shown as **% of Grand Total**, and a timeline on Date set to Months. Routes: MO-201 4.2.2 and MO-201 4.2.3.
7. Create a chart that shows sales by month distinguishing what is sold by each type. Filter by customer type. *Analyze PivotTable > Tools > PivotChart.* Date grouped by Months on the axis, Type as the series, and `Client Tye` in the **Filters** area. Routes: MO-201 4.3.1 for the chart, MO-201 4.3.2 for the field buttons.

The click paths for all of these are written out in [exercise 23](../ex23.en.md), which sets the same seven tasks against the same data.

## Notes on the source

- **There is no exercise 13, and this file is titled as though it were.** The instruction file opens `EXERCISE 13- Exercise Pivot Tables`, its folder is `Ejercicio 14 (tablas dinámicas)`, and its required-files line names `Exercise 14_Tables (students).xlsx`. The previous years' folder has no `Ejercicio 13` directory at all, no thirteenth workbook and no thirteenth instruction file. The gap is real, and the title on this one is the only trace of it left.
- **The document has a heading that reads `EXERCISE 1`** above the task table, with nothing following it and no exercise 2. It is a leftover from a template.
- **There is no soft drinks category.** Task 3 says to filter by category and choose soft drinks. The ten categories are Beer, Desserts, Entrees, Main course, Non-alcoholic beverages, Pasta, Pizza, Salads, Tacos and Wine. `Non-alcoholic beverages` is the one the task means, and it is 6,861 rows and 162,125 in revenue. Say so when the task is set, or the student will spend the time hunting a filter value that does not exist.
- **`Client Tye`** is the heading of column L, missing the p of Type. It is kept as it is in the CSV, because the PivotTable field list shows the heading and a corrected export would stop matching the workbook.
- **`Vino 9 ` carries a trailing space**, the only one of the 69 products that does. It does not collide with any other product name, so it groups on its own correctly, and it will sit oddly in any sorted list of products.
- **`Tip` is one rate per order, not per line.** It is a decimal between 0.05 and 0.20 repeated down every line of the ticket. Summing it is meaningless, and averaging it weights each order by how many things were on it. Use it as a rate against an order total or leave it out; no task here reads it.
- **The command column names menus that Excel does not have.** `Fields, Items, and Assemblies` is `Fields, Items, & Sets` in the English product, and `Assemblies` looks like a back-translation of the Spanish `conjuntos`. `Analyze PivotTable > Tools > PivotChart` and `Analyze PivotTable > Filter > Insert Timeline` are the pre-2019 ribbon wording, where the tab is now **PivotTable Analyze**. The commands are still findable; the strings are not quotable.
- **Task 5 says seller and task 1 says waiter, for the same column.** Column E is `Waiter`. There is no seller field. Task 3 also says seller. All three mean column E.
- **The whole exercise is a duplicate of what the current set teaches as exercise 23, part B.** Same 26,608 rows, same seven tasks, same order. The current file is the one with the click paths written out; this one is the ancestor and the reason exercise 23 has two versions.
