# Homework 11 · Advanced filters

Six extractions from one flat table of farmers' market sales, each with a different shape of criterion: a single threshold, two conditions that must both hold, two conditions where either will do, a criterion computed from the data itself, a range between two numbers, and one that combines conditions with a restricted set of output columns. All six go through the **Advanced Filter** dialog rather than the filter arrows, because three of the six cannot be expressed with the arrows at all. Hand in the workbook with the six result blocks laid out to the right of the data.

**Objectives** MO-200 3.3.1, MO-200 4.2.1, MO-201 3.1.1

## What to do

Using the Farmers' Market Sales information, generate the following filters, starting in cell `H5`.

1. A filter holding only the observations whose sales are greater than `$100,000`.
2. A filter with products whose location is Center and whose season is Autumn.
3. A filter with meat products in both Spring and Summer.
4. A filter with products whose sales are higher than the average.
5. A filter with products whose code is greater than 10 and less than 40.
6. A filter with Spring vegetable products and sales of less than 50,000. It must show only the product and the sales.

Every one of the six is the same route: **Data** tab, **Sort & Filter** group, **Advanced**. In the **Advanced Filter** dialog select **Copy to another location**, set **List range** to `$A$5:$E$89`, set **Criteria range** to the small block holding the copied headers and the conditions, set **Copy to** to the top left cell of the destination, and click **OK**.

The criteria blocks are built the same way for all six. Copy the header text from row 5 into the top of the block, character for character, then write the conditions underneath: conditions on the same row are combined with AND, conditions on different rows with OR.

- **Filter 1.** Header `Sales`, one row underneath holding `>100000`.
- **Filter 2.** Headers `Location` and `Season` side by side, one row underneath holding `Center` and `Autum` on the same row, which is the AND.
- **Filter 3.** Headers `Product` and `Season` side by side, two rows underneath: `Meat` and `Spring` on the first, `Meat` and `Summer` on the second. `Meat` has to be repeated on both rows, because the two rows are alternatives and each must stand on its own. This is the OR.
- **Filter 4.** A computed criterion. The header cell must be blank or hold text that matches no column header, and the cell underneath holds `=E6>AVERAGE($E$6:$E$89)`, with the first reference relative so it walks down the list and the range absolute so the average stays put. Route MO-200 4.2.1 for the AVERAGE. A computed criterion under a real header is the single most common way this filter fails; Excel then reads the formula's result, `TRUE` or `FALSE`, as a literal to match.
- **Filter 5.** The header `Code` twice, side by side, with `>10` and `<40` on the same row underneath. The same field appearing twice on one criteria row is how a between test is written.
- **Filter 6.** Headers `Product`, `Season` and `Sales` side by side, with `Vegetables`, `Spring` and `<50000` on one row. To restrict the output columns, type `Product` and `Sales` into two cells at the destination before opening the dialog, then set **Copy to** to those two cells rather than to a single cell. The dialog returns only the columns whose headers it finds there.

## Checks

The row counts each filter returns, header row not counted:

| Filter | Condition | Rows returned |
|---|---|---|
| 1 | Sales greater than 100,000 | 27 |
| 2 | Center and Autum | 5 |
| 3 | Meat in Spring or Summer | 12 |
| 4 | Sales above the average of 91,259.238095 | 28 |
| 5 | Code greater than 10 and less than 40 | 27 |
| 6 | Vegetables, Spring, sales under 50,000 | 1 |

Filter 2 returns exactly the five Center rows for Autum, one per product:

| Code | Location | Product | Season | Sales |
|---|---|---|---|---|
| 10 | Center | Meat | Autum | 170,500 |
| 10 | Center | Fruit | Autum | 239,610 |
| 10 | Center | Dairy, eggs and honey | Autum | 63,000 |
| 10 | Center | Pastries | Autum | 126,750 |
| 10 | Center | Vegetables | Autum | 350,550 |

Filter 3 returns 12 rows because six locations each sell meat in both Spring and Summer. If it returns 6, only one season made it into the criteria block; if it returns 18, the Autum rows came along too.

Filter 5 returns 27 rows, being the 12 rows of code 20 and the 15 rows of code 30. If it returns 42, the test was written as greater than or equal to 10 and the Center rows are included; if it returns 39, code 40 came along.

Filter 6 returns one row and two columns:

| Product | Sales |
|---|---|
| Vegetables | 32,500 |

That is Hill Park in Spring. If the result carries five columns, the destination headers were not typed before the dialog was opened. If it returns more than one row, the sales threshold was not applied.

Filters 1 and 4 differ by one row, which is the useful check on filter 4: 27 rows clear 100,000, 28 clear the average of 91,259.238095, and the extra row is the one sitting between the two thresholds. Two filters returning the same count means the computed criterion was not computed and the filter fell back to the threshold above it.

## Notes on the source

- The Tareas folder holds no homework 10. The set runs 1 to 9 and then jumps to 11. Nothing has been renumbered here to close the gap.
- The instruction sheet names the required file `Hmw11_Excel(students)_Advanced Filters`, with a space before `Filters`. The file in the folder is `Hmw11_Excel(students)_AdvancedFilters.xlsx`, without it.
- The instructions say the filters start in cell `H5` and say nothing more about layout. Six results and six criteria blocks do not fit at one address, and the largest result is 28 rows deep. Where blocks two to six go, and where their criteria ranges sit, is left to the student. Laying the six results down column `H` with a few blank rows between them, and putting the criteria blocks further right, is one workable arrangement, but it is an inference and not something the source states.
- The instructions write the second filter as "Location in the Center and Autumn Season". The data spells the season `Autum`. A criterion typed as `Autumn` returns nothing, and correcting the data instead of the criterion changes the file the answers are checked against. The same applies to `West lake`, though no filter here matches on it.
- The instructions write the first threshold as `$ 100,000` with a currency symbol and a thousands separator. The sales column is plain numbers with no currency format, so the criterion has to be typed as `>100000`.
- Filter 3's wording, "A filter with both Spring and Summer Meat Products", reads like an AND but is an OR: no single row can be both Spring and Summer. Two criteria rows, not two conditions on one row.
- The header row on row 5 sits under a merged banner on row 2 with two blank rows between. Advanced Filter takes the list range explicitly, so the gap causes no trouble, but selecting the list by clicking one cell and pressing `Ctrl+A` picks up the right block only because rows 3 and 4 are empty. Set the list range by hand.
