# Exercise 12 · The IFS function against nested IF

Week 7, sessions 13 and 14, where the syllabus teaches nested IF. COBERTURA.md calls this the one exercise in the pack with no week assigned in the syllabus and puts it here, because the contrast it sets up is exactly the one session 14 is about. The same four-band classification gets written three times in parallel columns, once with nested `IF`, once with `IFS`, and once with `IFS` closed by `TRUE`. Hand in the workbook with all three columns filled on both sheets, and be ready to say which of the three you would keep.

**Objectives** MO-200 4.2.3, MO-200 2.2.5, MO-201 3.1.1

`IFS` checks conditions in order and returns the value paired with the first one that is TRUE. It replaces a stack of nested `IF` calls and it reads left to right instead of inward. It also has one behaviour worth planning for: when no condition is TRUE it returns `#N/A`. Sheet Ex2 has a student who lands there, which is the point of the third column.

Do not confuse this with exercise 11. The Spanish name of `IFS` is `SI.CONJUNTO`, and the Spanish names of `SUMIFS`, `COUNTIFS` and `AVERAGEIFS` end in `.SI.CONJUNTO`. The folder names for exercises 11 and 12 differ by one dot. The functions have nothing in common beyond the word.

## What to do

### Sheet Ex1

1. Column B, rows 2 to 31: give each score its rating using nested `IF`. Three levels of nesting, because four bands need three tests. Write it once in `B2` and fill down.
2. Column C: the same result using `IFS`. Four condition and value pairs, no nesting.
3. Column D: `IFS` again, but with `TRUE` as the last condition so the final rating becomes the default and catches anything the earlier tests missed.

Order the conditions from the top band down, or from the bottom band up, and stay consistent. `IFS` stops at the first TRUE, so a test written out of order returns the wrong band without raising an error.

### Sheet Ex2

4. Column E, rows 3 to 10: the average of the three marks. Use `AVERAGE` over `B3:D3` and fill down.
5. Show column E with no decimal places. Do it from the **Home** tab, **Number** group, not by retyping the numbers. The value underneath stays as it was, and that matters for the next three columns: `IFS` reads the stored value, not the displayed one.
6. Column F: the observation for each average using nested `IF`.
7. Column G: the same using `IFS`.
8. Column H: `IFS` with `TRUE` as the last condition.

Julieta Marín is the row the exercise is built around. Her marks are 20, 22 and 23, which average 21.67, above the top of the published scale. Columns F and G return `#N/A` for her. Column H returns whatever value you paired with `TRUE`. Compare the three cells side by side before you decide which formula you would ship.

## Exam routes used here

### MO-200 4.2.3, conditional operations with IF

1. Click the result cell.
2. Go to the **Formulas** tab, **Function Library** group, click **Logical**, and click **IF**.
3. In the **Function Arguments** dialog, click in the **Logical_test** box and build the comparison, for example click cell `A2` and type `>=900`.
4. Click in the **Value_if_true** box and type the text without quotation marks. The dialog adds them for you and shows the finished value to the right of the box.
5. Click in the **Value_if_false** box and do the same. Leaving it empty returns FALSE, which is almost never what the task wants.
6. Read **Formula result =** at the bottom of the dialog.
7. Click **OK**.
8. Lock any reference that must not move before filling down: put the insertion point on it in the formula bar and press `F4`.
9. Fill down and spot check one row on each side of the boundary.

![Function Arguments, open on IF](../../../img/en/function-arguments-if.png)

*The three boxes steps 3 to 5 fill in. Leaving Value_if_false empty is what returns FALSE, and the Formula result line at the foot is the answer the cell will hold once OK is clicked.*

**Short route, not graded.** Type `=IF(A2>=900,"Excellent","Good")` by hand. Faster, and a quotation mark in the wrong place gives an error with no preview to catch it.

**Shortcut.** `Shift+F3` with the insertion point inside an existing IF reopens **Function Arguments** on that formula, which is the fastest way to repair a nested condition.

**How to check it.** Change one source value so it sits exactly on a boundary, 900 or 750 or 500. A `>=` test and a `>` test differ on that one row, and that is where the exam puts its check.

### MO-201 3.1.1, part B, nesting one function inside another

This is the part the exam is actually testing, and it is what column B asks for on both sheets.

1. Build the outer `IF` with the route above, up to step 5.
2. Click into the **Value_if_false** box, the one that has to receive the nested function. Leave it empty.
3. Look at the **Name Box**, at the left end of the formula bar. While a Function Arguments dialog is open it stops showing the cell reference and becomes a function drop-down.
4. Open it and pick `IF` again from the list of recently used functions, or pick **More Functions...** to open **Insert Function** and choose from **Or select a category:** and **Select a function:**.
5. The Function Arguments dialog is replaced by the inner function's own dialog. Fill its boxes and do not click OK yet. To go back out, click the outer function's name inside the formula bar; the outer dialog returns with the nested call already in place.
6. Click **OK** once, at the outer level. One OK commits the whole nest.

![The Insert Function dialog](../../../img/en/insert-function.png)

*What More Functions... opens from the Name Box drop-down at step 4. Choose the category first and then the function, and the inner dialog takes the place of the outer one without disturbing the formula already under construction.*

### MO-201 3.1.1, part A, IFS

1. Select the cell that will hold the formula.
2. Go to the **Formulas** tab, **Function Library** group, click **Logical**, and click **IFS**.
3. The **Function Arguments** dialog opens. Its boxes are `Logical_test1`, `Value_if_true1`, `Logical_test2`, `Value_if_true2`, and so on. New pairs appear as you fill the ones above.
4. Click into `Logical_test1` and build the first comparison. Click into `Value_if_true1` and type the text without quotation marks.
5. Press Tab through the pairs. Excel evaluates each one live and shows the result to the right of the box, so a band written out of order shows up here.
6. For the default, type `TRUE` into the last `Logical_testN` box and the catch-all text into the matching `Value_if_trueN`.
7. Read **Formula result =** at the bottom and click **OK**.

**Short route, not graded.** Type the whole thing into the cell. It works, and on a four-band ladder the parentheses are easy enough to keep straight. The dialog earns its place on the nested `IF` column, where a student who types three levels blind gets the parentheses wrong and loses the whole item.

**How to check it.** Click into the cell and press `Shift+F3`. If the formula was built cleanly, **Function Arguments** reopens on `IFS` with each condition in its own box. If the whole formula sits inside `Logical_test1`, it was typed as text.

### MO-200 2.2.5, apply number formats

This objective is the ribbon one on purpose. Certiport separates it from 2.2.6 precisely so that one item tests the Number group and the other tests the dialog. Do not answer this one from Format Cells unless the task says so.

1. Select `E3:E10`. Select the numbers only, not the header.
2. Go to the **Home** tab, **Number** group.
3. Open the **Number Format** list at the top of the group. It reads **General** by default. Pick **Number**.
4. Click **Decrease Decimal** until the count reaches zero.

**Short route, not graded.** Rounding the values with `ROUND` inside the average formula. That changes the stored number rather than its appearance, and the exercise wants the display changed and the value left alone, so the two `IFS` columns keep reading the real average.

**How to check it.** Select `E3`. The **Number Format** list must read **Number**, and the formula bar must still show the full average with its decimals. If the formula bar shows a whole number, the value was rounded rather than formatted.

- `H10` must show the value you paired with `TRUE`, and it must be the only cell in column H that differs from column G.
- Change Andrea Chávez's first mark from 20 to 4. Her average drops to 10.00 and every one of F, G and H must move from Good to Regular. Anything that stays put was typed rather than calculated.
