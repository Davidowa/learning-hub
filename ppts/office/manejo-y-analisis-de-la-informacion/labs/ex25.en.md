# Exercise 25 · What-if analysis with Goal Seek, data tables and PMT

Three small financial models, built from nothing. A cleaning product that has to find its break-even volume, a car loan that has to show a payment for every combination of rate and term, and a currency trade that has to show a profit for every combination of buy and sell price. Goal Seek answers the first, a one-variable data table answers the second, and a two-variable data table answers the third. The student hands in one workbook with the three models on three sheets, each with its table filled and its inputs still live. It lands in week 16, sessions 31 and 32, the week that also carries the final project presentations, so the models are short on purpose.

**Objectives** MO-200 2.2.5, MO-201 2.2.2, MO-201 3.4.2, MO-201 3.4.4

Data tables are the third what-if tool and they are not a numbered objective on either exam. Goal Seek and Scenario Manager are MO-201 3.4.2, PMT is MO-201 3.4.4, and the **Data Table** dialog sits on the same menu as both without appearing in the objective domain. The syllabus asks for it anyway, in the line "Goal Seek, data tables and scenario analysis", so it is taught here and graded on the result rather than the route.

## The data

There is no workbook. Exercise 25 ships as a `.docx` and nothing else, which means the three models are typed from scratch. That is a reasonable challenge and an expensive one in a week that has project presentations in it. Everything the source specifies is set out below, ready to be typed or pasted; where the source leaves a number open, it says so and gives an example to work with.

## What to do

### Model 1

1. Type the labels in column A and the values and formulas in column B, as set out above. Format B4, B5, B6, B9 to B14 as currency with two decimals and B7 as a percentage. Route: MO-200 2.2.5.
2. Read the net income off B14. That is the first answer.
3. Find the volume at which the company breaks even. Select B14, then use Goal Seek to drive it to 0 by changing B3. Route: MO-201 3.4.2.
4. Write down the answer, then put 50,000 back in B3. Goal Seek overwrites the input cell with a plain number and leaves nothing behind that says it ran.
5. Build a one-variable data table for net income across the nine volumes. Put the nine volumes down a column, put `=B14` in the cell one row above and one column to the right of the first volume, select the whole block including both, and run **Data Table** with B3 as the **Column input cell**.

### Model 2

6. Type the four labels down column A. Format B3 as currency and enter the list price.
7. Put a data validation rule on B4: **Decimal**, **between** 0 and 0.30. Format the cell as a percentage. Route: MO-201 2.2.2.
8. Put a data validation rule on B5: **List**, source `6,12,18,24`, with **In-cell dropdown** kept. Give both rules an input message and a Stop error alert, because sellers are the ones typing into this sheet.
9. Write the payment in B6 with PMT. Route: MO-201 3.4.4.
10. Build a one-variable data table down a column of rates, with B4 as the **Column input cell**.
11. Build the same table again with the terms laid across a row, using B5 as the **Row input cell**. That is the exercise's own instruction, "perform the same exercise, but this time enter the variants along the rows", and it is the step that shows what the two input boxes actually mean.

### Model 3

12. Type the five labels and the two formulas.
13. Build a one-variable data table for profit across the eight buy rates, with B4 as the **Column input cell**.
14. Build a two-variable data table: buy rates down the left column, sell rates across the top row, and `=B7` in the corner cell where the two meet. Select the whole rectangle and run **Data Table** with B6 in **Row input cell** and B4 in **Column input cell**.

## Exam routes used here

**Goal Seek. MO-201 3.4.2**

1. Make sure the target cell holds a formula and the cell you intend to change holds a value. Goal Seek refuses to change a formula cell, which is why B3 has to be a typed 50,000 and not `=something`.
2. Select the formula cell, B14.
3. **Data** tab, **Forecast** group, click **What-If Analysis**, then **Goal Seek...**. The dialog opens with three boxes.
4. **Set cell:** is already filled with the cell you selected. Confirm it.
5. Click into **To value:** and type `0` as a plain number. No equals sign and no cell reference; the box will not accept one.
6. Click into **By changing cell:** and click B3 on the sheet. One cell only.
7. Click **OK**.
8. **Goal Seek Status** reports the outcome with **Target value:** and **Current value:** so you can see how close it landed. Click **OK** to keep the new input, or **Cancel** to put the sheet back.

Typing numbers into B3 and watching B14 converges eventually and leaves no trace that any tool was used. Not graded.

Alt then A then W opens the What-If Analysis menu, then G for Goal Seek.

**Data Table, one variable**

1. Build the model first, with the variable in its own cell and the result in a formula cell that reads it.
2. Type the values to test down a column, one per row.
3. In the cell one row above the first value and one column to its right, type `=` and click the result cell. It shows the current answer.
4. Select the rectangle that holds both: the column of values, the reference cell, and the empty cells that will be filled.
5. **Data** tab, **Forecast** group, **What-If Analysis**, then **Data Table...**.
6. The values are in a column, so leave **Row input cell** empty and put the model's variable cell in **Column input cell**. Getting these two the wrong way round is the single commonest error and it produces a table of identical numbers or a column of errors.
7. Click **OK**.

To lay the values across a row instead, put the reference cell one column to the left and one row below the first value, and fill **Row input cell** rather than Column input cell.

**Data Table, two variables**

1. Put the first variable's values down the left column and the second variable's values across the top row.
2. Put `=` and the result cell in the corner where the row and the column meet.
3. Select the whole rectangle, corner cell included.
4. **Data** tab, **Forecast** group, **What-If Analysis**, **Data Table...**.
5. **Row input cell** takes the variable whose values run across the top. **Column input cell** takes the variable whose values run down the side.
6. Click **OK**.

A data table writes an array formula, `{=TABLE(B6,B4)}`, into every filled cell at once. You cannot edit or delete one cell of it. Select the whole filled block to clear it.

Two-variable tables recalculate on every keystroke anywhere in the workbook. If the sheet turns slow, go to **Formulas** tab, **Calculation** group, **Calculation Options**, and select **Automatic Except for Data Tables**, then press F9 when you want the table refreshed.

**Configure data validation. MO-201 2.2.2**

1. Select the cell that will carry the rule.
2. **Data** tab, **Data Tools** group, click **Data Validation**, the top half of the split button.
3. The dialog opens on the **Settings** tab. Open the **Allow** list: Any value, Whole number, Decimal, List, Date, Time, Text length, Custom.
4. For the rate, pick **Decimal**. A **Data** list appears; pick **between**, then type `0` in **Minimum** and `0.3` in **Maximum**.
5. For the term, pick **List** and type `6,12,18,24` in the **Source** box. Keep **In-cell dropdown** selected or there is no list to pick from.
6. Leave **Ignore blank** selected.
7. Without closing the dialog, go to the **Input Message** tab. Keep **Show input message when cell is selected** and fill **Title** and **Input message**.
8. Without closing, go to the **Error Alert** tab. Keep **Show error alert after invalid data is entered**, open the **Style** list and pick **Stop**, which refuses the entry outright. Fill **Title** and **Error message**.
9. Click **OK**. Three tabs configured in one operation, which is the point of the objective.
10. To catch values typed before the rule existed: **Data** tab, **Data Tools** group, click the **Data Validation** arrow, click **Circle Invalid Data**.

Typing the allowed values into a spare column and asking people to copy from it validates nothing. Not graded.

**PMT. MO-201 3.4.4**

1. Lay the inputs out in labelled cells first. The formula has to reference cells, not carry hard numbers.
2. Select B6.
3. **Formulas** tab, **Function Library** group, **Financial**, then **PMT**.
4. The **Function Arguments** dialog opens with **Rate**, **Nper**, **Pv**, **Fv**, **Type**.
5. **Rate**: the rate per period. Type `B4/12`. Putting the annual rate in raw is the single commonest wrong answer.
6. **Nper**: the number of payments. B5 already holds months, so it goes in as `B5`. Had it held years, it would be `B5*12`.
7. **Pv**: the amount borrowed. Enter it as `-B3` to get the payment back positive, or as `B3` to get it back negative. Decide once and stay consistent.
8. **Fv** and **Type** stay empty. Empty Fv means nothing is left at the end; empty Type means the payment falls at the end of each period.
9. Read **Formula result =** at the bottom before committing.
10. Click **OK**.
11. Format the answer as currency: Ctrl+1, **Number** tab, **Currency** in the **Category** list, two decimal places, **OK**.

Typing `=PMT(0.154/12,24,-250000)` returns the right payment and fails any item that says the payment has to update when the rate changes, because there is nothing to update.

**Apply a number format. MO-200 2.2.5**

Select the cells, press Ctrl+1, and use the **Number** tab of **Format Cells**. Pick the **Category** on the left, then set **Decimal places**, **Symbol** and the negative-number style on the right. The Currency and Percent buttons on the **Home** tab, **Number** group reach the default of each category and nothing else, so a task that names the decimal places or the symbol needs the dialog.

## Checks

### Model 1

The base case, at 50,000 units: revenue **3,500,000**, variable cost **1,500,000**, contribution **2,000,000**, profit before tax **500,000**, tax **75,000**, net income **425,000**.

Goal Seek lands on **37,500 units**. Sanity check without the tool: fixed costs 1,500,000 divided by the 40 per unit of contribution is exactly 37,500, and the tax rate does not move it, because fifteen per cent of zero is zero. After Goal Seek runs, B3 holds a number nobody typed and B14 reads zero, usually with a tail of decimals, because Goal Seek stops at a tolerance rather than landing exactly.

The data table:

| Units | Net income |
|---|---|
| 30,000 | -255,000 |
| 35,000 | -85,000 |
| 40,000 | 85,000 |
| 45,000 | 255,000 |
| 50,000 | 425,000 |
| 55,000 | 595,000 |
| 60,000 | 765,000 |
| 65,000 | 935,000 |
| 70,000 | 1,105,000 |

The step is 170,000 per 5,000 units all the way down, because the model is linear. The sign flips between 35,000 and 40,000, which brackets the 37,500 that Goal Seek found. If the whole column reads 425,000, the input cell went into the wrong box.

Two things about the negatives. The model as written applies the fifteen per cent to a loss, so 30,000 units shows -255,000 rather than -300,000. That is what the source describes and it is not how tax works. Worth a sentence in class.

Click one filled cell of the table and read the formula bar: it shows `{=TABLE(,B3)}` in braces. Braces mean an array, and an array is the fingerprint of the tool. A column of typed numbers is not a data table.

### Model 2

With a list price of 250,000 at 15.40% over 24 months, PMT returns **-12,169.23**, or 12,169.23 if Pv was entered negative. Multiply it by 24 and you get 292,061, comfortably above the 250,000 borrowed, and the difference is the interest. If payment times term comes out below the amount borrowed, the annual rate went in undivided or the term went in as years.

Same price, the two-way table:

| Rate | 6 months | 12 months | 18 months | 24 months |
|---|---|---|---|---|
| 15% | 43,508.45 | 22,564.58 | 15,596.20 | 12,121.66 |
| 17% | 43,756.85 | 22,801.19 | 15,832.52 | 12,360.57 |
| 19% | 44,005.92 | 23,039.14 | 16,070.87 | 12,602.15 |
| 21% | 44,255.64 | 23,278.44 | 16,311.23 | 12,846.41 |
| 23% | 44,506.02 | 23,519.08 | 16,553.59 | 13,093.33 |
| 25% | 44,757.05 | 23,761.05 | 16,797.95 | 13,342.88 |

Those numbers hold only for a 250,000 car. What holds for any price is the shape: the payment falls steeply as the term lengthens and rises gently as the rate climbs, and the rate matters far more at 24 months than at 6.

The validation: click B4 and the input message balloon appears. Type 0.45 and a titled Stop box refuses it. Click B5 and a dropdown arrow appears on the right edge with exactly four entries. Type 9 and it is refused. Then go to **Home** tab, **Editing** group, **Find & Select**, **Data Validation**, and both cells are selected and nothing else is.

### Model 3

For 10,000 dollars sold at 20.00, the one-variable table over the eight buy rates:

| Buy rate | Cost in pesos | Profit |
|---|---|---|
| 18.80 | 188,000 | 12,000 |
| 19.00 | 190,000 | 10,000 |
| 19.20 | 192,000 | 8,000 |
| 19.40 | 194,000 | 6,000 |
| 19.60 | 196,000 | 4,000 |
| 19.80 | 198,000 | 2,000 |
| 20.00 | 200,000 | 0 |
| 20.20 | 202,000 | -2,000 |

Profit falls by 2,000 for every 0.20 on the buy rate, which is the amount traded times the step, and it crosses zero exactly where the buy rate meets the sell rate. Any amount other than 10,000 scales all three columns and leaves the crossing point where it is.

The two-variable table has to be symmetrical about its diagonal of zeros: every cell where the buy rate equals the sell rate reads 0, everything above and to the right of that line is profit, everything below and to the left is loss. If the zeros run the wrong way, the **Row input cell** and the **Column input cell** were swapped.

Click one filled cell and the formula bar reads `{=TABLE(B6,B4)}`, with both arguments filled. A one-variable table shows one argument and a comma.

## Notes on the source

**There is no workbook.** Exercise 25 is the only one of the twenty-five that ships as instructions alone. The three models are built from scratch, which is good practice and costs class time that week 16 does not have, since the same two sessions carry the final project presentations. Capturing the model 1 figures into a starter workbook ahead of the session is the cheap fix, and the table above holds everything needed to do it.

**Two of the three models are underspecified.** Model 2 never states the car's list price and model 3 never states the amount traded. The rate bands, the terms and the exchange-rate ladder are all given; the base numbers are not. The worked example above uses 250,000 for the car and 10,000 dollars for the trade, which are stand-ins, and the check tables say so. Every student's numbers will differ and every student's table has to show the same shape.

**Scenario Manager is named and never used.** The opening paragraph of the source lists the three what-if tools, and then all three models use Goal Seek and data tables. None of them defines a scenario. That leaves half of MO-201 3.4.2 without a practice file. Adding a fourth task to model 2, three named scenarios for a cheap, a mid and a luxury trim with a Scenario Summary report, would close it in about fifteen minutes. It is not added here, because the exercise as the professor wrote it does not ask for it.

**The tax on a loss.** Model 1 multiplies profit before tax by the tax rate whatever its sign, so the loss-making rows of the data table come out fifteen per cent smaller than the loss actually is. Left as the source has it, because changing the formula changes the break-even answer's arithmetic, and because the wrong result is a good five minutes of discussion.

**Data tables and calculation mode.** A two-variable data table recalculates on every keystroke in the workbook. The setting that stops it, **Automatic Except for Data Tables**, lives in **Formulas** tab, **Calculation** group, **Calculation Options**, and it is worth mentioning here because it is the one place in the course where the default calculation mode is the wrong choice.
