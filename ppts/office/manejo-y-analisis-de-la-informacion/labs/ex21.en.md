# Exercise 21 · Lookups across three table shapes

Three reference tables, three shapes, one key. The student names each inventory block, fills in the description, unit and cost of four items in each of the three lookup tables, and hands the workbook back with the formulas visible in the formula bar. Only the third block is horizontal, so HLOOKUP answers one third of the exercise and the folder name is misleading. The second block is the interesting one: its key sits in the second column, which is exactly the case VLOOKUP cannot handle, and the exercise forces INDEX with MATCH without ever naming either function. It lands in week 13, sessions 25 and 26, next to Exercise 20.

**Objectives** MO-200 2.3.1, MO-200 4.1.2, MO-201 3.2.1

## What to do

1. Name Inventory 1. Select `B4:E2586` and define the name `Base1`, scope Workbook. Route: MO-200 2.3.1.
2. Name Inventory 2. Select `L4:O2586` and define the name `Base2`, scope Workbook. Start at column L, not column M, or INDEX counts its columns from the wrong place.
3. Name Inventory 3. Select `W3:AJ6` and define the name `Base3`, scope Workbook. Leave column V out. It holds the four row labels, not data, and HLOOKUP has to find the item codes in the first row of the range.
4. Fill Table 1 with VLOOKUP against `Base1`. In `H5` write `=VLOOKUP($G5,Base1,2,FALSE)`, then column 3 in `I5` and column 4 in `J5`. Fill down to row 8. Route: MO-201 3.2.1, VLOOKUP, plus MO-200 4.1.2 for using the name in place of an address.
5. Fill Table 2 with INDEX and MATCH against `Base2`. VLOOKUP is not available here, because the key sits in the second column of the block and the description sits to its left. In `R5` write `=INDEX(Base2,MATCH($Q5,$M$4:$M$2586,0),1)`, then change the last argument to 3 in `S5` and 4 in `T5`. Fill down to row 8. Route: MO-201 3.2.1, INDEX with MATCH nested.
6. Fill Table 3 with HLOOKUP against `Base3`. In `Y11` write `=HLOOKUP($X11,Base3,2,FALSE)`, then row 3 in `Z11` and row 4 in `AA11`. Fill down to row 14. Route: MO-201 3.2.1, HLOOKUP.
7. The fourth row of every table returns `#N/A`. That result is correct, because those three keys are not in the data. Wrap each formula in `IFERROR(...,"Not in catalogue")` and note on the sheet which code is missing from which catalogue.

## Exam routes used here

**Define a named range. MO-200 2.3.1**

1. Select the range to be named.
2. **Formulas** tab, **Defined Names** group, click **Define Name**.
3. The **New Name** dialog opens. In the **Name** box type `Base1`. The name has to start with a letter, an underscore or a backslash, and it cannot be a cell address.
4. Open the **Scope** list and pick **Workbook**.
5. Check the **Refers to** box. It has to hold an absolute reference, `=Inventory!$B$4:$E$2586`. To reselect, click the small collapse arrow at the right of the box, drag on the sheet, and click the arrow again.
6. Click **OK**.

Typing the name into the Name Box at the left end of the formula bar also creates it. That route always scopes to Workbook, offers no Comment, and never shows the reference it built, so a wrong range goes unnoticed. Not graded.

To confirm all three names: **Formulas** tab, **Defined Names** group, **Name Manager**, or Ctrl+F3.

**VLOOKUP. MO-201 3.2.1**

1. Select the cell that will hold the lookup.
2. **Formulas** tab, **Function Library** group, **Lookup & Reference**, then **VLOOKUP**.
3. **Lookup_value**: the cell holding the key. Lock the column with a single dollar, `$G5`, so the formula survives being filled right as well as down.
4. **Table_array**: type `Base1`. A name is already absolute, which is why naming the block first removes the F4 step candidates forget.
5. **Col_index_num**: the column counted from the first column of Table_array, not from column A of the sheet.
6. **Range_lookup**: type FALSE. Leaving it empty is not the same as FALSE. Empty means TRUE, and TRUE on this data returns nonsense, because the catalogue is sorted by cost and not by code.
7. Click **OK**.

**MATCH. MO-201 3.2.1**

1. **Formulas** tab, **Function Library** group, **Lookup & Reference**, then **MATCH**.
2. **Lookup_value**: the key.
3. **Lookup_array**: one single row or one single column. MATCH refuses a two-dimensional range, which is why `$M$4:$M$2586` goes in this box and `Base2` does not.
4. **Match_type**: 0 for exact.
5. Click **OK**. MATCH returns a position number, not a value.

**INDEX with MATCH nested. MO-201 3.2.1**

1. **Formulas** tab, **Function Library** group, **Lookup & Reference**, then **INDEX**.
2. The **Select Arguments** dialog opens first, headed INDEX, with the line "This function has multiple argument lists. Please select one of them." Pick `array,row_num,column_num` and click **OK**.
3. The Function Arguments dialog opens with **Array**, **Row_num** and **Column_num**. In **Array** type `Base2`.
4. Leave the cursor in **Row_num** and nest MATCH through the Name Box at the left end of the formula bar.
5. Fill MATCH's three boxes, then click the word INDEX in the formula bar to come back out.
6. Fill **Column_num** with 1, 3 or 4.
7. Click **OK** once, at the INDEX level.

The finished formula reads as one expression, `=INDEX(Base2,MATCH($Q5,$M$4:$M$2586,0),1)`. Two cells wired together, one holding MATCH and one holding INDEX, is a different answer.

**HLOOKUP. MO-201 3.2.1**

The same dialog as VLOOKUP with **Row_index_num** in place of Col_index_num, and the key searched across the top row of Table_array instead of down its first column. In `Base3` the top row holds the item codes, so row 2 returns the description, row 3 the unit and row 4 the cost.

**Reference a named range in a formula. MO-200 4.1.2**

Start typing the first letters of the name inside the formula. Formula AutoComplete lists it with a tag icon; press Tab to insert it. Or press F3 to open the **Paste Name** dialog, select the name and click **OK**. Dragging over the cells so the formula fills with `$B$4:$E$2586` gives the same arithmetic and is the wrong answer when the task says to use the name.

## Notes on the source

The workbook ships with three defined names already in it, `Table1`, `Table2` and `Table3`, pointing at the three answer blocks. They are left over from building the exercise and nothing in the instructions uses them. Leave them or delete them, but do not confuse them with the three names the exercise asks for.

The fourth key in each table is deliberately absent from its catalogue, and the original instructions never mention it. Item 485501480 is nowhere in Inventory 1 or Inventory 2, and item 450812524 is nowhere in Inventory 3, though 450812520 is, one digit away. Task 7 above is the fix. Without it the student hands in a sheet with three `#N/A` cells and no way to tell an error from a mistake.
